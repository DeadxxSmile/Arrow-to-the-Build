# Bundled ESO Skill Catalog

ATTB includes one canonical player-skill catalog at `resources/data/eso-skill-catalog.json`.

The renderer reaches it through the `#catalog` subpath declared in `package.json`, so there is one file rather than a main-process copy and a renderer copy that can drift apart. Regenerate it with:

```text
python tools/generate_skill_catalog.py
```

The generator validates permanent IDs, base/morph links, passive point counts, exact unlock-rank arrays, and morph prerequisites before writing. For Update 50 maintenance, `tools/skill_unlock_data.py` is the reviewed unlock-gate source table and `python tools/generate_skill_unlock_audit.py` writes the full human-readable ledger to `docs/maintenance/SKILL_UNLOCK_AUDIT_U50.md`.

## What the catalog records

The catalog is human-readable JSON and records:

- category and skill-line names;
- class association when applicable;
- maximum line rank;
- ultimate, active, morph, passive, Class Mastery, and Scribing entries;
- base-to-morph relationships;
- maximum purchasable passive ranks;
- exact skill-line rank requirements for base abilities and ultimates;
- exact per-point passive line-rank gates in `unlock_ranks`;
- the separate **base ability Rank IV** requirement for every morph in `requires_base_skill_rank`;
- ordinary Skill Point, Class Mastery, inherent/free, and tracking-only currency types;
- verification date, live-patch label, and source provenance for unlock timing.

Build JSON remains responsible for build-specific recommendation order, status, phase, notes, and images. This separation lets ATTB track every selected player skill without forcing every build author to duplicate the complete game catalog. Companion abilities remain in the separate companion system because they do not use the player Skill Point/skill-line progression model.

## Stable IDs

Build files reference catalog entries by `catalog_skill_id` (for example `herald__fatecarver`), not by display name. IDs are normally `{line_id}__{slugged_skill_name}` and are generated by `tools/generate_skill_catalog.py`.

Changing an existing ID is a breaking change for every build that references it. Renaming display text is not. Update 49/50 moved and renamed several skills; ATTB preserves already-shipped permanent IDs with explicit migration markers and display-name overrides so existing characters and community build files keep resolving.

## `required_rank`: skill-line rank, not character level

`required_rank` means **the rank of the skill line that contains the skill**, not the character's overall level. Examples:

- `herald__fatecarver` requires Herald of the Tome rank 4.
- `dual_wield__blade_cloak` requires Dual Wield rank 20.
- `assault__war_horn` requires Assault rank 4.
- `vampire__mist_form` requires Vampire rank 9.

The Character Tracker compares this value to the synced/manual rank for that exact line.

## Passive point gates

A multi-rank ESO passive can unlock each purchasable point at a different skill-line rank. A single `required_rank` is therefore not enough. ATTB stores the complete purchase sequence in `unlock_ranks`; `required_rank` is the first gate for convenience.

```json
{
  "id": "medium_armor__agility",
  "name": "Agility",
  "type": "Passive",
  "max_points": 2,
  "required_rank": 38,
  "unlock_ranks": [38, 46]
}
```

For a build that wants both points, its two `unlock_order` rows should therefore use ranks 38 and 46. The Build Editor does this automatically when adding passive ranks.

**Update 50 full-audit invariant:** every ordinary `skill_point` passive in the shipped catalog has exactly one `unlock_ranks` entry per purchasable point. Missing passive gates are treated as catalog-maintenance failures and are blocked by tests; the old conservative “wait until line max because we do not know” behavior remains only as a future-drift safety fallback.

## Morph gates are two-dimensional

A morph is not available merely because the skill line reached the original ability's line-rank gate. ESO also requires the base ability itself to reach **Rank IV**.

Every catalog morph therefore records both:

```json
{
  "type": "Morph",
  "required_rank": 4,
  "requires_base_skill_rank": 4
}
```

These fields mean different things:

- `required_rank`: required **skill-line** rank;
- `requires_base_skill_rank`: required rank of the **base ability itself**.

ATTB can prove the line-rank half from a character snapshot. Because the current character sync does not expose each base ability's internal I-IV training progress, a morph remains a **train** step rather than being falsely labeled immediately purchasable.

## Current audit baseline and sources

Catalog `0.6.0-u50-full-unlock-audit` was verified on **2026-08-09** against the live **Update 50 Inc. 2** environment. The source hierarchy is embedded in `unlock_gate_sources` in the JSON. The current ESO-Hub skill database is the primary unlock-rank source; ZeniMax live patch notes establish the live patch; a machine-readable community table is used only as a secondary cross-check and cannot override current live data.
